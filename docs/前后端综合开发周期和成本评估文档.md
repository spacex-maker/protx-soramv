## 2. 评估依据（项目真实复杂度）

## 2.1 前端复杂度（`protx-soramv`）

已具备以下业务域和工程底座：

- 多业务域：Workspace（创作/文件/媒体工具/PromptMarket/Embedding）、Community、OpenRobotX、Resume、支付订单、账号体系
- 多端体验：PC + 移动端响应式
- 统一基础能力：路由守卫、国际化（11语种）、主题系统、统一 Axios 拦截器
- 文件与存储：COS 分片上传、断点续传、节点管理、回收站

前端成熟度判断：**中高复杂度商业前端平台**。

## 2.2 后端复杂度（`productx-backend`）

基于仓库结构与依赖识别：

- 多模块 Maven 架构：`common` + `core`（C端）+ `manage`（管理端）
- 技术栈：Java17 + Spring Boot 3 + Spring Security + MyBatis-Plus + Redis + MySQL
- 高复杂业务链路：支付与回调、AI 任务、社区审核、对象存储多厂商适配、OAuth、向量检索能力
- 大体量代码信号：`core` 与 `manage` 均为千级 Java 文件规模（含 controller/service/mapper/entity）

后端成熟度判断：**高复杂度平台后端**。

## 3. 估算方法说明（给投资方看的“怎么得出”）

本评估采用三层方法：

1. **WBS 工作分解法**：按业务域拆分开发工作量（前端/后端/测试/运维）
2. **人月成本法**：按岗位全成本单价折算
3. **替代成本法**：因为系统已开发完成，用“同等能力重建成本”衡量当前资产价值

评估输出包含三种口径：

- **重建口径**：从 0 到 1 需要多少钱和多久
- **资产口径**：当前已完成系统折算价值
- **运维口径**：未来一年保持迭代需要多少钱

## 6. 已完成系统的“研发资产价值”估算（核心）

你现在前后端已开发完成，所以更合理的是看“当前资产值多少钱（替代成本）”。

## 6.1 折算模型

**研发资产价值 = 重建基准成本 × 完成系数 × 可复用系数**

建议取值：

- 重建基准成本：1,290 万
- 完成系数：0.80 ~ 0.95（系统已具备大量可运行业务域）
- 可复用系数：0.75 ~ 0.90（考虑技术债、文档、自动化、迁移成本）

## 6.2 结果区间

- 保守：1,290 × 0.80 × 0.75 ≈ **774 万**
- 中位：1,290 × 0.88 × 0.82 ≈ **931 万**
- 乐观：1,290 × 0.95 × 0.90 ≈ **1,103 万**

考虑市场沟通与商业谈判弹性，建议对外展示：

- **研发资产替代价值：800 万 ~ 1,400 万元（建议中位锚点 1,000 万）**
